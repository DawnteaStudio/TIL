# Codex 기본기: 필수 명령어와 세션 관리

AI 코딩 도우미 Codex를 효과적으로 활용하기 위해서는 기본적인 명령어 사용법과 세션 관리 체계를 이해하는 것이 중요하다. 이 글에서는 Codex의 핵심 명령어들을 살펴보고, 세션이 무엇이며 어떻게 관리되는지에 대해 설명한다.

## Codex 필수 명령어

Codex는 다양한 명령어를 통해 사용자의 환경 설정, 모델 제어, 세션 관리 등 광범위한 기능을 제공한다. 주요 명령어는 다음과 같다.

### 사용자 환경 및 모델 제어

*   `/logout`: 현재 활성화된 Codex 세션을 안전하게 종료하고 로그아웃한다.
*   `/permissions`: Codex의 접근 권한 설정을 변경한다. 이를 통해 특정 기능이나 파일 접근에 대한 제어를 할 수 있다.
*   `/model`: 사용할 AI 모델을 변경하고, 해당 모델의 추론 레벨을 설정한다.
    *   **예시**: `/model gpt-4 level 3` 명령어를 사용하면 GPT-4 모델을 선택하고 추론 깊이를 3단계로 설정한다. 이는 모델의 응답 방식이나 깊이에 영향을 미친다.
*   `/personality`: Codex의 대답 스타일이나 어조를 정의하여, 사용자의 선호에 맞는 상호작용을 할 수 있도록 돕는다.

### 세션 및 상태 관리

*   `/status`: 현재 실행 중인 각 터미널의 Codex 세션 상태를 상세히 보여준다. 이 명령어를 통해 여러 터미널에서 동시에 작동하는 Codex 인스턴스들의 활성화 여부와 현재 상태를 한눈에 파악할 수 있다.
*   `/clear`: 현재 터미널 화면을 정리한다. 이는 세션 자체에 영향을 주지 않으면서 터미널의 가독성을 높이는 데 사용된다.

### 성능 및 기록 관리

*   `/fast`: 응답 속도를 빠르게 설정하지만, 이 모드에서는 일반적으로 AI 모델의 토큰 소모량이 증가할 수 있다. 빠른 피드백이 필요할 때 유용하다.
*   `codex resume`: 이전에 작업했던 Codex 세션들의 목록을 조회한다. 이를 통해 과거의 작업 맥락을 쉽게 확인하고 다시 시작할 수 있다.
*   `codex resume --last`: 가장 최근에 작업했던 디렉토리를 기준으로 마지막 세션을 즉시 재개한다. 이는 이전에 진행하던 작업을 빠르게 이어갈 때 효율적이다.

## Codex 세션 관리의 이해

Codex에서 '세션'은 개발자가 각 터미널에서 시작하는 독립적인 Codex 인스턴스를 의미한다. 각 세션은 고유한 작업 맥락과 대화 기록을 가지며, 이는 Codex의 효율적인 활용에 중요한 기반이 된다.

### 세션의 정의와 관리

각 터미널에서 `codex` 명령어를 실행하면, 해당 터미널에 연결된 하나의 Codex 세션이 시작된다. 이 세션은 독립적으로 운영되며, `/status` 명령어를 통해 여러 터미널에서 활성화된 세션들의 상태를 개별적으로 모니터링할 수 있다. 이처럼 세션별로 독립적인 관리가 가능하기 때문에, 여러 프로젝트를 동시에 진행하거나 다른 맥락의 작업을 전환할 때 혼동 없이 Codex를 활용할 수 있다.

### 세션 데이터 저장 구조

Codex는 사용자의 환경 설정 및 세션 데이터를 특정 디렉토리에 저장하여 관리한다.

*   `.codex` 디렉토리: Codex의 전반적인 구성 및 환경 설정 파일들이 저장되는 경로이다.
*   `.codex/sessions` 디렉토리: 활성화되었던 세션들의 목록 정보가 이 디렉토리에 포함된다.
*   `.codex/sessions/...jsonl` 파일: 각 세션에서 이루어진 대화 내용들이 `.jsonl` 확장자를 가진 파일 형태로 저장된다.

이러한 저장 구조 덕분에 `codex resume` 명령어는 과거 세션의 대화 기록을 탐색하여 중단했던 작업을 이어서 진행할 수 있게 된다. 개발자는 이 구조를 통해 작업 중인 모든 세션의 기록을 영구적으로 보존하고 필요할 때마다 재활용할 수 있다.

## 결론

Codex의 필수 명령어들을 숙지하고 세션 관리 메커니즘을 이해하는 것은 AI 코딩 도우미를 더욱 효과적으로 활용하는 데 필수적이다. 명령어들을 적재적소에 사용하고, 세션의 개념 및 데이터 저장 방식을 파악함으로써 개발 워크플로우를 최적화하고 생산성을 향상시킬 수 있다.
